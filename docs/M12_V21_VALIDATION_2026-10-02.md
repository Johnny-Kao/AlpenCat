## Implementation review

The base already contained all three v2.1 features, including passing the
current backend only during M14 replanning. This session did not duplicate them.

The bucket previously blended average total duration directly with the global
prediction. That flattens the global slope inside an observed bucket and mixes
observed transfer cost with the queried transfer term.

The correction now retains paired EMAs of work size and compute duration:

```text
residual = EMA(compute) - (current_setup + current_slope * EMA(work))
prediction = max(0, global_compute(query) + weight * residual) + transfer(query)
```

The same bounded sample weight (maximum 0.75), logarithmic buckets, and 10%
uncertainty/preference band remain. Residuals are recalculated against the
current fit, avoiding stale offsets after regression updates.

Regression coverage:
- exact linear predictions at unseen sizes inside an observed bucket;
- transfer-free prediction and exact addition of measured transfer cost;
- existing local nonlinearity, preference hold/release, historical M5 crossover.

## Real model replay and generalization limits

`crates/runtime-cost-model/examples/m5_matrix.rs` feeds the measured p50 values
through the actual Rust cost model, separating task families by tap count.

- Initial decisions after observing all measured shapes: 15/15 faster-backend matches.
- Leave one size out of training: 13/15 matches.
- Held-out misses: 32K/h128 and 16K/h256.

15/15 is an in-sample observation replay, not independent validation or a
universal accuracy guarantee. Local correction cannot repair a bucket with no
observations. Hysteresis is a stability policy, not a guarantee of picking the
instantaneously faster backend at every near-tie.

The Swift harness bypasses Runtime execution adapters. Its measurements are
then replayed through M12; this is not an end-to-end Metal Runtime adapter test.
